# Positive Framing

When writing guidance — rules, memories, instructions, code comments, commit messages, PR descriptions — lead with the desired behavior. Convert corrections into positive direction.

| Input (correction) | Output (guidance) |
|---|---|
| "stop using git rebase" | "Use git merge for stack integration" |
| "don't approve without running tests" | "Run tests locally before approving" |
| "never mock the database" | "Test against a real database" |

The first sentence of every guideline describes what to do. Why follows if needed, but the action comes first.
